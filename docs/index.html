Da limpeza dos dados brutos à inteligência aplicada

Este painel resume os principais achados do desafio de dados da LH Nautical: da EDA da tabela de pedidos, passando pela modelagem do schema no PostgreSQL, até a previsão de demanda e o motor de recomendação.

Cada número aqui está documentado e explicado, com as premissas assumidas, no relatório completo do desafio.

Diagnóstico da base

tabela de pedidos, sem tratamento

Posso confiar nesses dados para tomar decisões? Uma leitura exploratória antes de qualquer limpeza.

Pedidos por status

Só ~70% dos pedidos estão pagos — o resto está em rascunho, confirmado ou cancelado. É por isso que a base de pedidos sozinha não deve virar métrica de receita.

Diagnóstico

Os dados são utilizáveis, mas não estão prontos para virar métrica de negócio sem tratamento e relacionamento com outras tabelas. A distribuição do valor total é larga (cauda longa plausível — PF e PJ/frota convivem na mesma tabela), sem outlier isolado absurdo. Não há nulos em valor, status ou cliente, mas o vendedor está nulo em ~49% das linhas. Conclusão: confiável para leitura operacional, não para receita sem filtrar por status.
